# Hot Reload

**Enregistrez le fichier, le menu est à jour. Aucune commande, aucun redémarrage.** Avec le hot reload activé, zMenu surveille votre dossier `inventories/` et applique chaque modification tout seul : modifiez un fichier dans votre éditeur, envoyez-le en SFTP ou récupérez-le depuis git, et les joueurs voient la nouvelle version instantanément, même s'ils ont le menu ouvert.

```yaml
# config.yml
hot-reload:
  enable: true
  delay-milliseconds: 500
```

Lancez ensuite `/zm reload config` une fois (ou `/zm reload`) pour démarrer la surveillance. À partir de là, vous n'avez plus jamais besoin de `/zm reload` pour vos inventaires.

:::tip Parfait pour créer des menus
Ouvrez le menu en jeu, placez votre éditeur à côté, et concevez en direct : déplacez un bouton, changez une ligne de lore, corrigez un prérequis, enregistrez, et le menu se rouvre avec votre modification sur la même page. Combiné au [convertisseur DeluxeMenus](./convert-deluxemenus), c'est le moyen le plus rapide de peaufiner vos menus convertis.
:::

## Ce qu'il fait

| Vous... | zMenu... |
|---------|----------|
| Modifiez un fichier | Recharge l'inventaire |
| Créez un fichier | Charge le nouvel inventaire |
| Supprimez un fichier (ou un dossier entier) | Décharge l'inventaire et le ferme pour ceux qui le regardent |

Les sous-dossiers de `inventories/` sont aussi surveillés.

## Les joueurs gardent leur place

Les joueurs qui regardent un inventaire au moment où il est rechargé voient la nouvelle version s'ouvrir instantanément :

- sur la **même page**,
- avec les **mêmes inventaires précédents**, donc un bouton retour ouvre aussi la nouvelle version.

Si l'inventaire est déchargé (fichier supprimé, ou `enable: false` ajouté dedans), il est fermé.

## Une erreur ne casse jamais un menu

Un fichier qui ne peut pas être chargé (erreur de syntaxe YAML, type de bouton inconnu, taille invalide...) n'est **pas appliqué** : la version précédente reste chargée et jouable, et l'erreur est affichée dans la console jusqu'à ce que vous corrigiez le fichier. Vous pouvez enregistrer un travail inachevé sans rien casser pour vos joueurs.

## Fonctionne partout

- **Enregistrements regroupés** : les éditeurs de texte enregistrent souvent un fichier en plusieurs étapes. zMenu attend `delay-milliseconds` (500 ms par défaut) après la dernière modification, donc un enregistrement ne déclenche qu'un seul rechargement.
- **Docker, Pterodactyl, WSL, partages réseau, SFTP** : en plus des événements du système de fichiers, le dossier est scanné toutes les deux secondes, donc les modifications sont détectées même là où le système de fichiers n'envoie aucun événement.
- **Sauvegardes et git** : si le dossier `inventories/` est supprimé puis recréé (restauration de sauvegarde, `git checkout`...), il est de nouveau surveillé automatiquement.
- **Windows** : toute l'arborescence est surveillée avec un seul handle, donc les sous-dossiers peuvent toujours être renommés ou supprimés pendant que le serveur tourne.
- **Aucun rechargement inutile** : un fichier est rechargé quand son contenu ou sa date de modification change. Le réenregistrer sans changement le recharge quand même, mais la même version n'est jamais rechargée deux fois.

## Configuration

| Option | Défaut | Description |
|--------|--------|-------------|
| `enable` | `false` | Active le hot reload |
| `delay-milliseconds` | `500` | Temps d'attente après la dernière modification d'un fichier avant de le recharger |

Activer ou désactiver l'option prend effet après `/zm reload` ou `/zm reload config`, ou en moins de deux secondes quand elle est modifiée depuis le dialogue de configuration en jeu.

:::info Ce qui est surveillé
Seul le dossier `inventories/` est surveillé. Les fichiers listés dans [`specify-path-menus`](./configurations/config-yml), les patterns, les commandes et les dialogues nécessitent toujours `/zm reload`.
:::

## Logs console

Chaque détection, rechargement, déchargement et erreur est affiché dans la console avec le préfixe `[HotReload]` :

```
[zMenu] [HotReload] Inventory hot reload enabled, watching .../plugins/zMenu/inventories (native recursive watch, 12 file(s), 12 loaded inventory(ies), scan every 2000ms, delay 500ms).
[zMenu] [HotReload] Change detected on example.yml, reloading the inventory...
[zMenu] [HotReload] Inventory example.yml reloaded in 14ms, reopened for 1 player(s).
```

Avec [`enable-debug`](./configurations/config-yml#enable-debug) à `true`, chaque événement de fichier, chaque changement trouvé par le scan et chaque fichier ignoré (inchangé) est aussi affiché.

## Dépannage {#depannage}

**Rien ne se passe quand j'enregistre un fichier**
1. Vérifiez que la ligne `Inventory hot reload enabled` apparaît au démarrage ou après `/zm reload`.
2. Vérifiez que le fichier est dans `inventories/` et n'est pas chargé via `specify-path-menus`.
3. Activez `enable-debug` pour voir si la modification est détectée.

**Ma modification n'est pas appliquée**
Le fichier contient probablement une erreur : cherchez-la dans la console. La version précédente reste chargée tant que le fichier n'est pas valide.

## Quand l'activer

- Pendant la création ou la modification de menus, pour voir vos changements instantanément
- Sur un serveur de test ou de développement
- Sur les serveurs de production où les menus sont déployés par SFTP ou git et doivent être pris en compte sans commande
