# Migrer depuis DeluxeMenus

**Vous venez de DeluxeMenus ? Vous n'avez rien à réécrire.** zMenu convertit vos menus DeluxeMenus existants en inventaires zMenu avec une seule commande : items, slots, commandes de clic, prérequis, commandes d'ouverture et plus encore sont traduits automatiquement.

```
/zm convert deluxemenus
```

C'est tout. Chaque menu de `plugins/DeluxeMenus/gui_menus/` est converti, et vous gardez toute votre configuration tout en profitant de tout ce que zMenu apporte en plus : [pagination](./configurations/buttons/types/pagination), [patterns](./configurations/patterns), [données joueur](./configurations/player-data), [dialogues](./configurations/dialogues), [formulaires Bedrock](./configurations/bedrock), [hot reload](./hot-reload) et bien plus.

:::tip Pourquoi migrer ?
- **Zéro réécriture** : vos menus sont convertis en quelques secondes, pas réécrits à la main pendant des jours.
- **Rien de caché** : tout ce qui ne peut pas être converti à l'identique est listé en haut du fichier converti et dans la console.
- **Sécurisé par conception** : une fonctionnalité que zMenu ne peut pas reproduire n'accorde jamais plus que DeluxeMenus. Un prérequis non supporté refuse toujours, et une action non supportée arrête les actions qui la suivent.
- **DeluxeMenus non requis** : le convertisseur lit directement les fichiers YAML. DeluxeMenus n'a pas besoin d'être installé, ni même activé.
:::

## Démarrage rapide {#demarrage-rapide}

1. Copiez votre dossier DeluxeMenus dans `plugins/` (ou laissez-le en place) pour que les menus soient dans `plugins/DeluxeMenus/gui_menus/`.
2. Lancez `/zm convert deluxemenus` (ou `/zm convert dm`) depuis la console ou en jeu.
3. Lisez le résultat : chaque menu affiche ✔ s'il est converti, ou ✘ avec la raison s'il ne l'est pas.
4. Ouvrez les fichiers convertis et vérifiez la liste **Not converted exactly** en haut de chaque fichier, s'il y en a une.
5. **Désactivez DeluxeMenus** (retirez son jar), sinon ses commandes d'ouverture entrent en conflit avec celles converties.
6. Lancez `/zm reload` pour charger les inventaires convertis et leurs commandes.

:::tip Combinez-le avec le hot reload
Activez le [hot reload](./hot-reload) avant de convertir : les menus convertis sont chargés dès qu'ils sont écrits, et chaque correction que vous faites en les relisant est appliquée instantanément, sans `/zm reload`.
:::

## Commande

| Commande | Permission | Description |
|----------|-----------|-------------|
| `/zm convert deluxemenus` | `zmenu.convert` | Convertir tous les menus de `plugins/DeluxeMenus/gui_menus/` (sous-dossiers inclus) |
| `/zm convert deluxemenus <menu>` | `zmenu.convert` | Convertir un seul menu, par nom de fichier, avec ou sans `.yml` |
| `/zm convert dm [menu]` | `zmenu.convert` | Alias court |

Exemple de résultat :

```
✔ shop → inventories/converted/deluxemenu/shop.yml + command
✔ ranks → inventories/converted/deluxemenu/ranks.yml + command (2 not converted exactly, see the top of the file)
✘ broken: this is not a DeluxeMenus menu
Converted 2/3 menus. Review them, then run /zm reload to load them.
```

## Où sont les fichiers convertis ? {#ou-sont-les-fichiers-convertis}

| Quoi | Emplacement |
|------|-------------|
| Menus source (lecture seule) | `plugins/DeluxeMenus/gui_menus/**/*.yml` |
| Inventaires convertis | `plugins/zMenu/inventories/converted/deluxemenu/<menu>.yml` |
| Commandes d'ouverture converties | `plugins/zMenu/commands/converted/deluxemenu/<menu>.yml` |

- Vos fichiers DeluxeMenus ne sont **jamais modifiés**.
- Un menu déjà converti n'est **jamais écrasé** : il est ignoré avec `already converted, delete ... to convert it again`. Supprimez le fichier converti pour convertir le menu à nouveau. Les fichiers de commandes ne sont pas écrasés non plus.
- Un fichier qui n'a ni `menu_title` ni `items` est ignoré avec `this is not a DeluxeMenus menu`.

Chaque fichier converti commence par un en-tête comme celui-ci :

```yaml
# Converted from the DeluxeMenus menu shop.yml by zMenu.
# Review it before use: https://docs.groupez.dev/zmenu/getting-started
#
# Not converted exactly:
# - shop.yml: the action "[meta] set points INTEGER 5" is not supported, the actions after it will not run
# - shop.yml: the requirement money_check "has meta" is not supported, it always denies
name: '&8Shop'
size: 27
items:
  # ...
```

## La commande d'ouverture

L'`open_command` de DeluxeMenus devient une [commande personnalisée](./configurations/custom-commands) zMenu :

```yaml
# DeluxeMenus
open_command:
  - shop
  - store
```

```yaml
# plugins/zMenu/commands/converted/deluxemenu/shop.yml
commands:
  shop:
    command: shop
    aliases:
      - store
    inventory: shop
```

La première commande devient la commande zMenu, les autres deviennent ses alias.

### Actions

Les commandes de clic, d'ouverture et de fermeture de DeluxeMenus sont converties en [actions](./configurations/buttons/actions) zMenu. Les modificateurs `<delay=ticks>` et `<chance=pourcentage>` sont conservés, où qu'ils soient dans la ligne.

| DeluxeMenus | Action zMenu |
|-------------|--------------|
| `[close]` | `close` |
| `[console]` | `console-command` |
| `[player]` | `player-command` |
| `[commandevent]` | `player-command` (avec événement de commande) |
| `[chat]` | `chat` |
| `[message]` / `[minimessage]` | `message` (couleurs legacy / MiniMessage) |
| `[broadcast]` / `[minibroadcast]` | `broadcast` (couleurs legacy / MiniMessage) |
| `[actionbar]` | `action-bar` |
| `[openguimenu]` / `[openmenu]` | `inventory` (arguments conservés) |
| `[connect]` | `connect` |
| `[refresh]` | `refresh` |
| `[sound]` / `[rawsound]` | `sound` (volume et pitch conservés) |
| `[broadcastsound]` / `[broadcastrawsound]` | `broadcast-sound` |
| `[broadcastsoundworld]` / `[broadcastrawsoundworld]` | `broadcast-sound`, joué à tout le serveur (avertissement) |
| `[takemoney]` / `[givemoney]` | `withdraw` / `deposit` (Vault) |
| `[giveexp]` / `[takeexp]` | Commande console `/xp add` (suffixe `L` = niveaux) |

Tout autre tag (`[meta]`, `[json]`, `[givepermission]`...) est signalé, et les actions qui le suivent **ne s'exécutent pas** : un menu ne peut donc jamais donner une récompense sans l'étape qui devait la précéder.

### Prérequis {#prerequis}

`open_requirement`, `view_requirement` et les prérequis de clic sont convertis en [prérequis](./configurations/requirements) zMenu, avec leurs `deny_commands` et `success_commands`.

| Type DeluxeMenus | zMenu | Négation (`!`) |
|------------------|-------|----------------|
| `has permission` | `permission` | Oui |
| `has permissions` | Un `permission` par entrée | Non, et `minimum` doit être égal au nombre de permissions |
| `string equals` | `placeholder` | Oui |
| `string equals ignorecase` | `placeholder` | Oui, avec un `output` littéral |
| `string contains` | `placeholder` | Oui, avec un `output` littéral |
| `string contains ignorecase` | `regex` | Oui, avec un `output` littéral |
| `>`, `>=`, `==`, `<=`, `<` | `placeholder` (numérique) | Non |
| `!=` | `placeholder` (comparé comme du texte, avertissement) | - |
| `regex matches` | `regex` | Oui |
| `string length` | `regex` | Non |
| `has money` | `money` (Vault) | Non |
| `has exp` (avec `level: true`) | `placeholder` sur `%player_level%` | Non |
| `has item` (matériau, `model_data`, `amount`) | `item` | Non |

Les noms longs (`has permission`), les noms courts (`hasperm`, `perm`) et les symboles sont tous reconnus, sans tenir compte de la casse.

`minimum_requirements` est supporté quand tous les prérequis sont optionnels. Quand des prérequis obligatoires et optionnels sont mélangés, zMenu les exige tous et le signale.

## Ce qui n'est pas converti

Tout ce qui suit est listé en haut du fichier converti et affiché dans la console avec le préfixe `[DeluxeMenus]` :

| Fonctionnalité | Comportement |
|----------------|--------------|
| Tags d'action non supportés | Signalés, les actions qui suivent ne s'exécutent pas |
| Types de prérequis non supportés (ou négation / options non supportées) | Signalés, le prérequis refuse toujours |
| `has item` avec `strict`, `name`, `lore`, `data`, `armor`, `offhand`, `name_contains`, `lore_contains`, `model_data_component` | Signalé, refuse toujours |
| `stop_at_success` | Tous les prérequis sont vérifiés |
| `refresh` (option du menu) | Seuls les items avec `update: true` sont rafraîchis |
| `args` (arguments du menu) | Non converti, utilisez les [arguments de commande](./configurations/custom-commands) |
| `enable_open_requirements_bypass_permissions` | Non converti |
| Options d'item `rgb`, `banner_meta`, `base_color`, `potion_effects`, `trim_material`, `trim_pattern`, `model_data_component`, `light_level`, `lore_append_mode` | Non converties, utilisez les [options d'item](./configurations/items/item) ou les [composants](./configurations/items/components) zMenu |
| Matériaux `stack-...` et `simpleitemgenerator-...` | Non convertis |

:::warning Relisez toujours le résultat
Le convertisseur fait le gros du travail, mais votre serveur est unique. Ouvrez chaque inventaire converti une fois, testez ses boutons et corrigez les lignes listées sous **Not converted exactly** avant de passer en production.
:::

## FAQ

**Puis-je reconvertir après avoir modifié un menu DeluxeMenus ?**
Oui. Supprimez le fichier converti dans `inventories/converted/deluxemenu/` (et sa commande dans `commands/converted/deluxemenu/` si vous voulez la régénérer), puis relancez la commande.

**Puis-je déplacer les fichiers convertis ?**
Oui. Ce sont des inventaires zMenu classiques : déplacez-les ou renommez-les où vous voulez dans `inventories/`. N'oubliez pas que le nom d'inventaire utilisé par `/zm open` et par le fichier de commande est le nom du fichier.

**Dois-je garder DeluxeMenus installé ?**
Non. Le convertisseur lit seulement les fichiers de `plugins/DeluxeMenus/gui_menus/`. Une fois la conversion faite, retirez DeluxeMenus : s'il reste activé, zMenu vous prévient que ses commandes d'ouverture entrent en conflit avec celles converties.

**Mon menu utilise des placeholders. Fonctionnent-ils toujours ?**
Oui. Les placeholders PlaceholderAPI sont conservés tels quels et résolus par zMenu.
