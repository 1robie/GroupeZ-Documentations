# Données joueur {/* #donnees-joueur */}

zMenu inclut un système de données joueur intégré qui vous permet de stocker et récupérer des valeurs spécifiques à chaque joueur. C'est parfait pour suivre la progression, créer des bascules, stocker des statistiques et plus encore.

## Comment ça fonctionne {/* #comment-ca-fonctionne */}

Les données joueur sont stockées dans une base de données (SQLite par défaut, MySQL/MariaDB en option) et persistent entre les redémarrages du serveur. Chaque joueur a son propre ensemble de paires clé-valeur.

## Accéder aux données joueur {/* #acceder-aux-donnees-joueur */}

### Placeholder

Utilisez le placeholder `%zmenu_player_value_<cle>%` :

```yaml
item:
  name: "&6Pieces : %zmenu_player_value_coins%"
  lore:
    - "&7Kills : %zmenu_player_value_kills%"
    - "&7Morts : %zmenu_player_value_deaths%"
```

### Commandes

```bash
# Definir une valeur (expire-after en secondes, 0 = n'expire jamais)
/zm players set <joueur> <cle> <expire-after> <valeur>

# Ajouter a une valeur (numerique)
/zm players add <joueur> <cle> <nombre>

# Obtenir une valeur
/zm players get <joueur> <cle>

# Supprimer une cle
/zm players remove <joueur> <cle>

# Supprimer une cle de TOUS les joueurs
/zm players removeall <cle>

# Soustraire une valeur (numerique)
/zm players subtract <joueur> <cle> <nombre>

# Effacer toutes les donnees d'un joueur
/zm players clear <joueur>

# Effacer toutes les donnees de tous les joueurs
/zm players clearall

# Lister toutes les cles pour un joueur
/zm players keys <joueur>
```

## Modifier les données avec des actions {/* #modifier-les-donnees-avec-des-actions */}

### L'action Data

```yaml
actions:
  - type: data
    action: SET      # SET, ADD, SUBTRACT, REMOVE
    key: "coins"
    value: "100"
    math: true       # Activer les expressions mathematiques
    seconds: 0       # Optionnel : si > 0, la valeur expire apres ce nombre de secondes
```

### Actions disponibles

| Action | Description | Exemple |
|--------|-------------|---------|
| `SET` | Définir à une valeur spécifique | `value: "100"` |
| `ADD` | Ajouter à la valeur actuelle | `value: "50"` |
| `SUBTRACT` | Soustraire de la valeur actuelle | `value: "25"` |
| `REMOVE` | Supprimer entièrement la clé | - |

### Expressions mathématiques {/* #expressions-mathematiques */}

Activez les maths avec `math: true` :

```yaml
actions:
  - type: data
    action: SET
    key: "total"
    value: "%zmenu_player_value_base%*1.5+100"
    math: true
```

## Exemples

### Système de pièces/monnaie {/* #systeme-de-piecesmonnaie */}

```yaml
# Afficher les pieces
items:
  coin-display:
    slot: 4
    item:
      material: GOLD_NUGGET
      name: "&6&lVos Pieces"
      lore:
        - "&7Solde : &e%zmenu_player_value_coins%"

  # Bouton ajouter des pieces
  add-coins:
    slot: 11
    item:
      material: GOLD_INGOT
      name: "&a&l+100 Pieces"
    actions:
      - type: data
        action: ADD
        key: "coins"
        value: "100"
      - type: message
        messages:
          - "&a+100 pieces !"
      - type: refresh

  # Depenser des pieces
  spend-coins:
    slot: 15
    item:
      material: DIAMOND
      name: "&b&lAcheter Diamant"
      lore:
        - "&7Cout : &e50 pieces"
    click-requirement:
      achat:
        clicks:
          - ALL
        requirements:
          - type: placeholder
            value: "%zmenu_player_value_coins%"
            action: SUPERIOR_OR_EQUAL
            number: 50
            deny:
              - type: message
                messages:
                  - "&cVous avez besoin de 50 pieces !"
        success:
          - type: data
            action: SUBTRACT
            key: "coins"
            value: "50"
          - type: console-command
            commands:
              - "give %player% diamond 1"
          - type: refresh
```

### Paramètre à bascule {/* #parametre-a-bascule */}

```yaml
items:
  toggle-notifications:
    type: SWITCH
    slot: 13
    placeholder: "%zmenu_player_value_notifications%"
    buttons:
      "true":
        item:
          material: LIME_DYE
          name: "&a&lNotifications : ON"
          lore:
            - "&7Cliquez pour desactiver"
        actions:
          - type: data
            action: SET
            key: "notifications"
            value: "false"
          - type: refresh

      "false":
        item:
          material: GRAY_DYE
          name: "&7&lNotifications : OFF"
          lore:
            - "&7Cliquez pour activer"
        actions:
          - type: data
            action: SET
            key: "notifications"
            value: "true"
          - type: refresh

    default:
      item:
        material: LIME_DYE
        name: "&a&lNotifications : ON"
      actions:
        - type: data
          action: SET
          key: "notifications"
          value: "false"
        - type: refresh
```

### Système de récompense quotidienne {/* #systeme-de-recompense-quotidienne */}

```yaml
items:
  # Systeme de recompense quotidienne
  daily-reward:
    slot: 22
    item:
      material: CHEST
      name: "&e&lRecompense quotidienne"
      lore:
        - "&7Reclamez votre recompense quotidienne !"
        - ""
        - "&7Derniere reclamation : &f%zmenu_player_value_last_daily%"
    click-requirement:
      recuperer:
        clicks:
          - ALL
        requirements:
          - type: placeholder
            value: "%zmenu_math_{zmenu_time_unix_timestamp}-{zmenu_player_value_last_daily}%"
            action: SUPERIOR_OR_EQUAL
            number: 86400  # 24 heures en secondes
            deny:
              - type: message
                messages:
                  - "&cVous avez deja reclame la recompense d'aujourd'hui !"
        success:
          - type: data
            action: SET
            key: "last_daily"
            value: "%zmenu_time_unix_timestamp%"
          - type: console-command
            commands:
              - "give %player% diamond 5"
          - type: data
            action: ADD
            key: "daily_streak"
            value: "1"
          - type: message
            messages:
              - "&aRecompense quotidienne reclamee !"
              - "&7Serie : &e%zmenu_player_value_daily_streak%"
          - type: sound
            sound: ENTITY_PLAYER_LEVELUP
```

## Configuration de la base de données {/* #configuration-de-la-base-de-donnees */}

Configurez le stockage dans `config.yml` :

```yaml
# Type de stockage : SQLITE, MYSQL, MARIADB ou NONE
storage-type: SQLITE

# Configuration de la base de donnees (pour MySQL/MariaDB)
database-configuration:
  table-prefix: "zmenu_"
  host: "localhost"
  port: 3306
  user: "username"
  password: "password"
  database: "zmenu"
```

### Convertir JSON en SQL

Si vous utilisiez précédemment le stockage JSON :

```
/zm players convert
```

Cela migre les données des fichiers JSON vers la base de données configurée.

## Valeurs par défaut {/* #valeurs-par-defaut */}

### default_values.yml

Quand une clé n'existe pas pour un joueur, `%zmenu_player_value_<cle>%` ne retourne pas un texte vide : il retourne `Key '<cle>' doesn't exist for this player`. Pour obtenir une valeur de départ propre, déclarez-la dans `plugins/zMenu/default_values.yml`. Le fichier est créé au premier démarrage et relu par `/zm reload` :

```yaml
values:
  # %zmenu_player_value_playtime_level% retourne 0 meme si la cle n'a jamais ete ecrite pour le joueur
  playtime_level: 0
  grandma: 0
  factory: 0
  mine: 0
  cookie: 0
```

La valeur par défaut ne s'applique qu'aux placeholders `%zmenu_player_value_<cle>%`, `%zmenu_player_expire_<cle>%` et `%zmenu_player_expire_format_<cle>%` ; elle ne **crée pas** la clé (`%zmenu_player_key_exist_<cle>%` reste `false` tant qu'aucune valeur n'est écrite). L'[exemple cookie clicker](./example-menus) s'appuie dessus.

### Autres façons de gérer les clés manquantes {/* #autres-facons-de-gerer-les-cles-manquantes */}

```yaml
# Dans les exigences, verifiez l'existence
- type: placeholder
  value: "%zmenu_player_value_coins%"
  action: SUPERIOR_OR_EQUAL
  number: 0  # Necessite une valeur par defaut (default_values.yml), sinon le placeholder n'est pas un nombre
```

Ou définissez des valeurs par défaut au premier accès :

```yaml
items:
  initialize:
    slot: 0
    view-requirement:
      requirements:
        - type: placeholder
          value: "%zmenu_player_value_initialized%"
          action: DIFFERENT
          target: "true"
    item:
      material: AIR
    actions:
      - type: data
        action: SET
        key: "coins"
        value: "0"
      - type: data
        action: SET
        key: "initialized"
        value: "true"
      - type: refresh
```

## Bonnes pratiques

1. **Utilisez des clés descriptives** : `daily_reward_claimed` et non `drc`
2. **Initialisez les valeurs par défaut** : définissez les valeurs initiales pour les nouveaux joueurs
3. **Utilisez les maths avec précaution** : assurez-vous que les valeurs sont numériques pour les opérations mathématiques
4. **Nettoyez les anciennes données** : utilisez `removeall` pour les clés inutilisées
5. **Sauvegardez votre base de données** : surtout avant les changements majeurs
6. **Documentez vos clés** : gardez une trace des données que vous stockez

## Conventions de nommage des clés {/* #conventions-de-nommage-des-cles */}
