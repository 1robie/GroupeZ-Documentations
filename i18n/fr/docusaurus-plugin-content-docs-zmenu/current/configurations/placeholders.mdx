# Placeholders

zMenu fournit des placeholders intégrés et prend en charge PlaceholderAPI pour le contenu dynamique dans vos inventaires.

## Placeholders intégrés

Ces placeholders sont disponibles sans plugins supplémentaires :

### Placeholders joueur

| Placeholder | Description | Exemple de sortie |
|-------------|-------------|-------------------|
| `%player%` | Nom du joueur | `Notch` |

### Placeholders de pagination

| Placeholder | Description | Exemple de sortie |
|-------------|-------------|-------------------|
| `%page%` | Numéro de la page actuelle | `1` |
| `%maxPage%` | Numéro de la page maximale | `5` |
| `%max-page%` | Numéro de la page maximale (alias) | `5` |
| `%zmenu_player_page%` | Page actuelle (format PAPI) | `1` |
| `%zmenu_player_next_page%` | Numéro de la page suivante | `2` |
| `%zmenu_player_previous_page%` | Numéro de la page précédente | `0` |
| `%zmenu_player_max_page%` | Page maximale (format PAPI) | `5` |
| `%zmenu_pagination_page_<contextId>%` | Page actuelle (index 0) d'un contexte de pagination | `0` |
| `%zmenu_pagination_page_one_indexed_<contextId>%` | Page actuelle (index 1) d'un contexte de pagination | `1` |
| `%zmenu_pagination_next_page_<contextId>%` | Numéro de la page suivante d'un contexte de pagination | `2` |
| `%zmenu_pagination_previous_page_<contextId>%` | Numéro de la page précédente d'un contexte de pagination (minimum `0`) | `0` |
| `%zmenu_pagination_max_page_<contextId>%` | Page maximale d'un contexte de pagination (`<contextId>:<defaut>` définit une valeur de repli) | `5` |

### Placeholders d'historique d'inventaire

| Placeholder | Description | Exemple de sortie |
|-------------|-------------|-------------------|
| `%zmenu_player_previous_inventories%` | Nombre d'inventaires précédents dans l'historique | `3` |

### Placeholders mathématiques

Effectuez des calculs directement dans votre configuration :

| Placeholder | Description | Exemple |
|-------------|-------------|---------|
| `%zmenu_math_<expression>%` | Calculer une expression mathématique (résultat brut, toujours décimal) | `%zmenu_math_5+5%` → `10.0` |
| `%zmenu_formatted_math_<expression>%` | Résultat formaté (2 décimales max, séparateur de milliers) | `%zmenu_formatted_math_1000+500%` → `1 500` |

**Opérations prises en charge :**
- Addition : `+`
- Soustraction : `-`
- Multiplication : `*`
- Division : `/`
- Puissance : `^`
- Parenthèses : `()`
- Fonctions : `abs`, `ceil`, `floor`, `sqrt`, `cbrt`, `log`, `log10`, `exp`, `signum`, `sin`, `cos`, `tan`... (les fonctions standard d'[exp4j](https://www.objecthunter.net/exp4j/)), par exemple `%zmenu_math_sqrt(16)+abs(-2)%`

**Utiliser d'autres placeholders dans une expression :** dans `%zmenu_math_...%`, écrivez les placeholders imbriqués avec des accolades au lieu de pourcentages (`{vault_eco_balance}` au lieu de `%vault_eco_balance%`). Ils sont résolus en premier, puis l'expression est calculée. Le résultat de `math` est un décimal brut (`10.0`) ; utilisez `formatted_math` pour obtenir un nombre propre. Une expression invalide (ou un placeholder qui n'est pas un nombre) provoque une erreur dans la console.

**Exemples :**
```yaml
lore:
  - "&7Resultat : %zmenu_math_10*5%"           # Sortie : 50
  - "&7Solde : %zmenu_formatted_math_{vault_eco_balance}*2%"
```

### Placeholders de données joueur

| Placeholder | Description |
|-------------|-------------|
| `%zmenu_player_value_<cle>%` | Obtenir la valeur des données joueur |
| `%zmenu_player_key_exist_<cle>%` | `true` si le joueur possède cette clé de données |
| `%zmenu_player_expire_<cle>%` | Timestamp d'expiration (millisecondes) de la donnée, `0` ou moins si elle n'expire jamais |
| `%zmenu_player_expire_format_<cle>%` | Temps restant/écoulé depuis l'expiration, formaté (ou le message "jamais") |
| `%zmenu_player_is_expired_<cle>%` | `true` si la donnée est expirée ou n'existe pas |

**Exemple :**
```yaml
lore:
  - "&7Pieces : &6%zmenu_player_value_coins%"
  - "&7Kills : &c%zmenu_player_value_kills%"
```

### Placeholders d'arguments de commande

| Placeholder | Description |
|-------------|-------------|
| `%zmenu_argument_<cle>%` | Obtenir la valeur d'un argument de commande |

Ce placeholder récupère les arguments passés via les commandes personnalisées configurées dans zMenu.

**Exemple :**

Configuration de la commande :
```yaml
# Dans commands/commands.yml
commands:
  punish:
    command: punish
    arguments:
      - player
    inventory: example_punish
```

Utilisation de l'argument dans votre inventaire :
```yaml
items:
  player-info:
    item:
      material: PLAYER_HEAD
      playerHead: "%zmenu_argument_player%"
      name: "&cPunir %zmenu_argument_player%"
      lore:
        - "&7Cliquez pour punir ce joueur"
```

Quand un joueur exécute `/punish Notch`, le placeholder `%zmenu_argument_player%` retournera `Notch`.

### Placeholders de placeholders globaux

| Placeholder | Description |
|-------------|-------------|
| `%zmenu_global_placeholders_<cle>%` | Obtenir la valeur d'un placeholder global |

**Exemple :**
```yaml
# Dans global-placeholders.yml
server-name: "Mon Serveur"

# Dans l'inventaire
name: "&6%zmenu_global_placeholders_server-name%"
```

### Placeholders de temps

| Placeholder | Description | Exemple de sortie |
|-------------|-------------|-------------------|
| `%zmenu_time_unix_timestamp%` | Timestamp Unix actuel (en secondes) | `1704067200` |
| `%zmenu_time_next_day_unix_timestamp%` | Timestamp Unix de demain (en secondes) | `1704153600` |
| `%zmenu_time_today_start_unix_timestamp%` | Timestamp du début d'aujourd'hui (en secondes) | `1704067200` |

### Placeholders d'inspection d'item

Inspectez les propriétés de n'importe quel item du menu ou de l'inventaire du joueur.

**Syntaxe :** `%zmenu_item_<source>:<slot>_<propriete>%`

| Source | Description |
|--------|-------------|
| `inventory` | Un slot de l'inventaire zMenu actuellement ouvert |
| `player` | Un slot de l'inventaire du joueur (0-35) |
| `armor` | Un emplacement d'armure (`helmet`, `chestplate`, `leggings`, `boots`) |

| Propriété | Description |
|-----------|-------------|
| `is_player_item` | `true` si l'item a été placé par le joueur |
| `is_zmenu_item` | `true` si l'item appartient à l'interface zMenu |
| `material` | Nom du matériau (ex. `DIAMOND`) |
| `amount` | Taille de la pile |
| `dura` / `max_dura` | Durabilité actuelle / maximale |
| `name` / `lore` | Nom affiché / lore complet |
| `custommodeldata` | Valeur de custom model data |
| `enchantments` / `flags` | Liste des enchantements / flags, séparés par des virgules |
| `unbreakable` | `true` si incassable |
| `potion_type`, `potion_extended`, `potion_upgraded`, `custom_potion_effects` | Informations de potion |
| `banner_patterns` | Liste des motifs de bannière |
| `firework_power`, `firework_effects` | Informations de feu d'artifice |
| `skull_owner` | Nom du propriétaire de la tête |
| `leather_color` | Couleur de l'armure en cuir |
| `book_title`, `book_author`, `book_pages` | Titre, auteur et nombre de pages d'un livre |
| `stored_enchantments` | Enchantements stockés dans un livre |
| `armor_trim` | Matériau/motif de la garniture d'armure |

:::info
Les placeholders d'item renvoient un texte vide si le joueur est hors ligne, si le slot est vide ou si l'item n'a pas la propriété. Une source non prise en charge donne un texte vide, et un placeholder sans propriété donne `invalid placeholder`. `name` et `lore` renvoient le texte legacy avec codes couleur `§` ; les lignes de `lore` sont séparées par des retours à la ligne.
:::

**Exemples :**
```yaml
lore:
  - "&7Materiau du slot 13 : %zmenu_item_inventory:13_material%"
  - "&7Casque : %zmenu_item_armor:helmet_material%"
  - "&7Quantite slot 0 : %zmenu_item_player:0_amount%"
```

### Placeholders d'inventaire joueur

Ces placeholders sont particulièrement utiles lorsque l'inventaire du bas est masqué avec `clear-inventory: true`, car ils permettent de vérifier l'espace disponible avant de donner des items (par exemple dans les menus de shop).

| Placeholder | Description | Exemple de sortie |
|-------------|-------------|-------------------|
| `%zmenu_player_empty_slots%` | Nombre de slots libres dans l'inventaire du joueur | `12` |
| `%zmenu_player_item_count_<MATERIAL>%` | Quantité totale d'un item spécifique dans l'inventaire | `64` |

**Exemples :**
```yaml
# Afficher les slots libres dans le lore
lore:
  - "&7Slots libres : &a%zmenu_player_empty_slots%"
  - "&7Diamants : &b%zmenu_player_item_count_DIAMOND%"

# Empecher l'achat quand l'inventaire est plein
click-requirement:
  requirements:
    - type: placeholder
      value: "%zmenu_player_empty_slots%"
      action: SUPERIOR_OR_EQUAL
      number: 1
      deny:
        - type: message
          messages:
            - "&cVotre inventaire est plein !"
```

### Placeholders de statistiques

| Placeholder | Description | Exemple de sortie |
|-------------|-------------|-------------------|
| `%zmenu_statistic_hours_played%` | Heures jouées (arrondi) | `42` |
| `%zmenu_statistic_time_played%` | Temps de jeu formaté | `1j 18h 30m` |

## Intégration PlaceholderAPI

zMenu prend entièrement en charge PlaceholderAPI. Tout placeholder PAPI fonctionne dans :
- Titres d'inventaire
- Noms d'items
- Lore d'items
- Messages
- Exigences
- Actions

### Expansions PlaceholderAPI populaires

Installez les expansions avec : `/papi ecloud download <nom>`

| Expansion | Placeholders | Exemple |
|-----------|-------------|---------|
| Player | `%player_name%`, `%player_health%`, `%player_level%` | `%player_name%` → `Notch` |
| Vault | `%vault_eco_balance%`, `%vault_eco_balance_formatted%` | `%vault_eco_balance%` → `1500.00` |
| Statistic | `%statistic_deaths%`, `%statistic_kills%` | `%statistic_deaths%` → `42` |
| Server | `%server_online%`, `%server_max_players%` | `%server_online%` → `50` |
| LuckPerms | `%luckperms_prefix%`, `%luckperms_primary_group_name%` | `%luckperms_prefix%` → `[Admin]` |

### Utilisation de PlaceholderAPI

```yaml
items:
  profile:
    slot: 4
    item:
      material: PLAYER_HEAD
      playerHead: "%player_name%"
      name: "&6Profil de %player_name%"
      lore:
        - "&8&m─────────────────"
        - ""
        - "&7Sante : &c%player_health%&7/&c%player_max_health%"
        - "&7Niveau : &a%player_level%"
        - "&7Solde : &6$%vault_eco_balance_formatted%"
        - ""
        - "&7Kills : &a%statistic_player_kills%"
        - "&7Morts : &c%statistic_deaths%"
        - ""
        - "&8&m─────────────────"
```

## Placeholders locaux

Définissez des placeholders spécifiques à un inventaire :

```yaml
# Dans votre fichier d'inventaire
local-placeholders:
  prix: "100"
  nom-item: "Epee speciale"

items:
  shop-item:
    item:
      name: "&6%nom-item%"
      lore:
        - "&7Prix : &a$%prix%"
```

## Modificateurs de placeholders

Les placeholders propres à zMenu (arguments de commande, `%page%`, `%player%`, saisies des formulaires Bedrock, saisies des dialogues...) peuvent être transformés directement dans le placeholder, en ajoutant un ou plusieurs modificateurs après un point :

```yaml
# /shop <category>
- "&7Categorie : &f%category.capitalize%"   # weapons -> Weapons
- "&7Page &f%page.pad:2%"                   # 3 -> 03
- "&7Nom : &f%name.trim.max:16%"            # les modificateurs peuvent etre enchaines
- "&7Quantite : &f%amount.default:1%"       # 1 quand l'argument est vide
- "console-command: give %player% diamond %amount.int.safe%"
```

| Modificateur | Exemple | Résultat |
|--------------|---------|----------|
| `upper` / `lower` | `%name.upper%` | Majuscules / minuscules |
| `capitalize` | `%name.capitalize%` | Première lettre en majuscule, le reste en minuscules |
| `trim` | `%name.trim%` | Retire les espaces autour |
| `length` | `%name.length%` | Nombre de caractères |
| `empty` | `%name.empty%` | `true` si vide |
| `isnumber` | `%amount.isnumber%` | `true` si la valeur est un nombre |
| `safe` | `%name.safe%` | Retire `;`, `&`, `§` et les retours à la ligne (sûr dans une commande) |
| `default:<valeur>` | `%amount.default:1%` | `<valeur>` si vide |
| `max:<n>` | `%name.max:16%` | Coupe à `<n>` caractères |
| `pad:<n>` | `%page.pad:3%` | Complète avec des zéros à gauche jusqu'à `<n>` caractères |
| `int`, `round`, `floor`, `ceil` | `%price.round%` | Nombre entier |
| `abs` | `%value.abs%` | Valeur absolue |
| `negative`, `even` | `%value.even%` | `true` / `false` |
| `0f`, `1f`, `2f`, `3f` | `%price.2f%` | Nombre avec 0 à 3 décimales |
| `comma` | `%price.comma%` | Séparateur de milliers (`1,234,567`) |
| `add_one`, `remove_one` | `%page.add_one%` | Valeur + 1 / - 1 |
| `add:<n>`, `sub:<n>` | `%page.add:10%` | Valeur + n / - n |

Un modificateur inconnu, un argument manquant ou un modificateur numérique appliqué à une valeur non numérique donne un résultat vide. Les anciens préfixes (`%upper_cle%`, `%lower_cle%`, `%capitalize_cle%`, `%add_one_cle%`, `%remove_one_cle%`) fonctionnent toujours.

:::info
Les modificateurs s'appliquent aux placeholders propres à zMenu, pas aux placeholders PlaceholderAPI. Pour PlaceholderAPI, utilisez les options de formatage de l'expansion.
:::

## Cache des placeholders

Pour de meilleures performances, vous pouvez activer le cache des placeholders dans `config.yml` :

```yaml
# Activer le cache PlaceholderAPI
enable-cache-placeholder-api: true

# Duree du cache en ticks (20 ticks = 1 seconde)
cache-placeholder-api: 20
```

:::warning
Le cache signifie que les placeholders ne se mettront pas à jour instantanément. Activez-le uniquement si vous avez des problèmes de performances et que vous en comprenez les implications.
:::

## Placeholders contextuels

Certains placeholders `%cle%` n'existent que dans un contexte précis. Ce ne sont pas des placeholders PlaceholderAPI (pas de préfixe `zmenu_`) et ils acceptent les [modificateurs](#modificateurs-de-placeholders).

| Placeholder | Disponible dans | Valeur |
|-------------|-----------------|--------|
| `%player%` | Actions et exigences, [dialogues](./dialogues), [formulaires Bedrock](./bedrock) | Nom du joueur |
| `%page%`, `%maxPage%`, `%max-page%` | Inventaires classiques avec pages (nom, items, actions) | Page actuelle / maximale |
| `%page%`, `%max_page%` | Chaque élément d'un bouton de [pagination](./buttons/types/pagination) / pagination dynamique | Page actuelle / total (`%max_page%` commence à 1) |
| `%index%` | Boutons dynamiques des [dialogues](./dialogues) et [formulaires Bedrock](./bedrock) | Index de l'élément généré |
| `%content%` | Formulaires Bedrock simple et modal | Texte de contenu du formulaire |
| `%type%`, `%old_text%`, `%new_text%`, `%char%` | `rename-requirements` de l'enclume | Voir [inventaires enclume](./inventories/inventory) |
| `%<cle>%` | Champs de dialogue / Bedrock | Valeur saisie par le joueur |

:::info
Un placeholder `%zmenu_argument_<cle>%` sans valeur (l'argument n'a pas été donné) reste inchangé dans le texte au lieu d'être remplacé par une chaîne vide.
:::

## Placeholders imbriqués

Vous pouvez utiliser des placeholders à l'intérieur d'autres placeholders :

```yaml
# Utilisation des donnees joueur dans les maths
lore:
  - "&7Double pieces : %zmenu_math_{zmenu_player_value_coins}*2%"
```

## Exigences avec placeholders

Utilisez des placeholders dans les exigences pour créer des conditions dynamiques :

```yaml
click-requirement:
  requirements:
    - type: placeholder
      value: "%vault_eco_balance%"
      action: SUPERIOR_OR_EQUAL
      number: 100
      deny:
        - type: message
          messages:
            - "&cVous avez besoin d'au moins 100$ !"
```

## Formatage des placeholders

### Nombres

Pour les nombres formatés, utilisez les variantes `_formatted` quand elles sont disponibles :
- `%vault_eco_balance_formatted%` au lieu de `%vault_eco_balance%`
- `%zmenu_formatted_math_<expr>%` au lieu de `%zmenu_math_<expr>%`

### Couleurs dans les placeholders

Certains placeholders incluent des codes couleur. Pour les conserver :
```yaml
name: "%luckperms_prefix% %player_name%"  # Garde les couleurs
```

## Débugger les placeholders

Si les placeholders ne fonctionnent pas :

1. **Vérifiez que PlaceholderAPI est installé**
   ```
   /papi info
   ```

2. **Testez le placeholder**
   ```
   /papi parse me %nom_placeholder%
   ```

3. **Vérifiez que l'expansion est installée**
   ```
   /papi list
   ```

4. **Installez les expansions manquantes**
   ```
   /papi ecloud download <expansion>
   /papi reload
   ```
