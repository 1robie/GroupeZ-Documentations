# Item Configuration

Items are the visual elements displayed in your inventory buttons. This page documents all available item configuration options.

## Basic Item Structure

```yaml
item:
  material: DIAMOND
  name: "&bMy Item"
  lore:
    - "&7Line 1"
    - "&7Line 2"
```

## Configuration Options

### material

The material type for the item. zMenu supports vanilla Minecraft materials and many custom item plugins.

```yaml
item:
  material: DIAMOND_SWORD
```

#### Material Loaders

zMenu supports many material sources through its loader system:

| Plugin               | Syntax                                                  | Price    | Link                                                                           |
|----------------------|---------------------------------------------------------|----------|--------------------------------------------------------------------------------|
| **Bukkit**           | `STONE`, `DIAMOND_SWORD`                                | Built-in | Vanilla Minecraft                                                              |
| **PlaceholderAPI**   | `%your_placeholder_material%`                           | Free     | [SpigotMC](https://www.spigotmc.org/resources/6245/)                           |
| **Armor (slot)**     | `armor:HEAD`, `armor:CHEST`, `armor:LEGS`, `armor:FEET` | Built-in | Player's equipped armor                                                        |
| **zHead**            | `zhd:<id>`                                              | Free     | [Polymart](https://polymart.org/resource/2070)                                 |
| **MagicCosmetics**   | `magic_cosmetics:HAT`, `magic_cosmetics:BAG`, etc.      | Paid     | [Polymart](https://polymart.org/product/6981/magic-cosmetics-gui-non-animated) |

| **ItemsAdder**       | `itemsadder:<item name>`                                | Paid     | [SpigotMC](https://www.spigotmc.org/resources/73355/)                          |
| **SlimeFun**         | `slimefun:<item name>`                                  | Free     | [GitHub](https://github.com/Slimefun/Slimefun4)                                |

| **Base64**           | `base64:<item in base64>`                               | Built-in | Import items as base64 string                                                  |

| **MMOItems**         | `mmoitems:<type>:<item id>`                             | Paid     | [SpigotMC](https://www.spigotmc.org/resources/39267/)                          |
| **BaseHead**         | `basehead-<head-url>`                                   | Built-in | Use a base64 head texture directly in the material field                       |

**Examples:**

```yaml
# Vanilla material
material: DIAMOND_SWORD

# Player head (use the player-head key, see below)
player-head: "%player%"

# Custom head from zHead
material: "zhd:123"

# ItemsAdder custom item
material: "itemsadder:my_namespace:ruby_gem"

# Oraxen custom item
material: "oraxen:amethyst_sword"
```

### translated-name

Provides per-language translations of the item name. Each entry maps a `locale` to a `name`, and the plugin uses the one matching the player's client language. If no locale matches, the default `name` value is used instead.

<Tabs>
    <TabItem value="translatedName" label="translatedName">
        ```yaml
        item:
          material: DIAMOND_SWORD
          name: "&b&lShiny Diamond"
          translatedName:
            - locale: fr-fr
              name: "Nom en français"
            - locale: it-it
              name: "Nome in italiano"
        ```
    </TabItem>
    <TabItem value="translated-name" label="translated-name">
        ```yaml
        item:
          material: DIAMOND_SWORD
          name: "&b&lShiny Diamond"
          translated-name:
            - locale: fr-fr
              name: "Nom en français"
            - locale: it-it
              name: "Nome in italiano"
        ```
    </TabItem>
</Tabs>

The name is displayed in the player's client language. Players whose locale is not listed fall back to the default `name`.

### lore

The description lines shown below the item name.

```yaml
item:
  material: DIAMOND_SWORD
  name: "&6&lLegendary Sword"
  lore:
    - "&7A powerful weapon"
    - ""
    - "&7Damage: &c+50"
    - "&7Speed: &a+10%"
    - ""
    - "&eClick to equip!"
```

Each list item is a new line. Empty strings (`""`) create blank lines.

---

### lore-type

Define how the lore should interact with existing item lore. This is especially useful when using material loaders (ItemsAdder, Oraxen, etc.) where the loaded item already has lore.

<Tabs>
    <TabItem value="replace" label="REPLACE (default)">
        ```yaml
        item:
          material: "oraxen:custom_item"
          lore:
            - "&7This replaces all existing lore"
          lore-type: REPLACE
        ```
    </TabItem>
    <TabItem value="append" label="APPEND">
        ```yaml
        item:
          material: "itemsadder:namespace:item"
          lore:
            - ""
            - "&eClick to use!"
          lore-type: APPEND
        ```
    </TabItem>
    <TabItem value="prepend" label="PREPEND">
        ```yaml
        item:
          material: "zitems:legendary_sword"
          lore:
            - "&6&lLEGENDARY"
            - ""
          lore-type: PREPEND
        ```
    </TabItem>
</Tabs>

**Available Types:**

| Type      | Description                                  |
|-----------|----------------------------------------------|
| `REPLACE` | Replace the existing lore entirely (default) |
| `APPEND`  | Add lines after the existing lore            |
| `PREPEND` | Add lines before the existing lore           |

### amount

The stack size of the item.

```yaml
item:
  material: DIAMOND
  amount: 64
```

You can also use placeholders:

```yaml
item:
  material: DIAMOND
  amount: "%zmenu_player_value_coins%"  # Dynamic amount
```

---

### amount-type

Control how the `amount` value is applied when the item is built.

| Value | Description |
|-------|-------------|
| `SET` | Set the amount to exactly the given value (default) |
| `ADD` | Add the given value to the item's current amount |
| `REMOVE` | Subtract the given value from the item's current amount |

```yaml
item:
  material: DIAMOND
  amount: 5
  amount-type: ADD
```

### hide-tooltip

Completely hide the item tooltip when hovering over the item in the inventory.

```yaml
item:
  material: DIAMOND
  name: "&6&lHidden Tooltip" # You can still set a name and lore, but they won't be visible in the tooltip
  hide-tooltip: true
```

---

### hide-additional-tooltip

Hide the additional tooltip line that shows enchantments, attributes, etc. The item name and lore will still be visible.

```yaml
item:
  material: DIAMOND_SWORD
  name: "&6&lHidden Additional Tooltip"
  enchantments:
    - SHARPNESS,5
  hide-additional-tooltip: true
```

### glow

Add an enchantment glow effect without showing enchantments. Equivalent to adding `HIDE_ENCHANTS` flag with a dummy enchantment.

```yaml
item:
  material: NETHER_STAR
  name: "&6&lSpecial Item"
  glow: true
```

### player-head

Display a player's head. The material is automatically set to `PLAYER_HEAD`.

```yaml
item:
  player-head: "%player%"  # Current player's head
  name: "&a%player%'s Head"
```

You can also use a specific player name:

```yaml
item:
  player-head: "Notch"
```

:::tip
You don't need to specify `material: PLAYER_HEAD` when using `player-head`. The plugin handles this automatically.
:::

### url

Use a custom head texture URL (base64 encoded texture).

```yaml
item:
  material: PLAYER_HEAD
  url: "eyJ0ZXh0dXJlcyI6eyJTS0lOIjp7InVybCI6Imh0dHA6Ly90ZXh0dXJlcy5taW5lY3JhZnQubmV0L3RleHR1cmUv..."
  name: "&6Custom Head"
```

Get head textures from sites like [minecraft-heads.com](https://minecraft-heads.com/).

### color

Set the dye color for leather armor pieces or tipped-arrow/splash-potion items. Accepts an RGB or ARGB value as comma-separated integers.

```yaml
# Leather armor dyed cyan
item:
  material: LEATHER_CHESTPLATE
  color: "0,170,170"         # R,G,B

# ARGB format (alpha channel first)
item:
  material: LEATHER_HELMET
  color: "255,255,0,0"       # A,R,G,B
```

### potion

Turn the item into a potion (or splash / lingering potion). Requires the material to be a potion type (`POTION`, `SPLASH_POTION`, `LINGERING_POTION`, or `TIPPED_ARROW`).

```yaml
item:
  material: SPLASH_POTION
  potion: STRENGTH
  level: 2
  splash: true
  extended: false
```

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `potion` | String | — | Potion type (e.g. `SPEED`, `STRENGTH`, `HEALING`). See the [Bukkit PotionType docs](https://hub.spigotmc.org/javadocs/bukkit/org/bukkit/potion/PotionType.html) |
| `level` | Integer | `1` | Effect amplifier (1 = level I, 2 = level II, …) |
| `splash` | Boolean | `false` | Make a splash potion |
| `extended` | Boolean | `false` | Extended duration potion |
| `arrow` | Boolean | `false` | Tipped arrow instead of a drinkable potion |
| `color` | String | — | Custom potion particle color in `R,G,B` format |

---

### banner

Display a banner with custom patterns. Requires the material to be a banner type (e.g. `WHITE_BANNER`, `RED_BANNER`).

```yaml
item:
  material: WHITE_BANNER
  banner: WHITE         # Base color (DyeColor)
  patterns:
    - "RED:STRIPE_TOP"    # color:pattern
    - "BLUE:CROSS"
```

The `banner` key sets the **base color** (`DyeColor`). Each entry in `patterns` is formatted as `COLOR:PATTERN_TYPE`.

Available pattern types: [PatternType Javadoc](https://hub.spigotmc.org/javadocs/bukkit/org/bukkit/block/banner/PatternType.html)
Available dye colors: [DyeColor Javadoc](https://hub.spigotmc.org/javadocs/bukkit/org/bukkit/DyeColor.html)

### firework

Define a firework rocket or firework star item.

```yaml
item:
  material: FIREWORK_ROCKET
  firework:
    star: false
    flicker: true
    trail: true
    type: BALL_LARGE      # FireworkEffect.Type
    colors:
      - "255,0,0"         # Red (R,G,B or A,R,G,B)
      - "0,255,0"         # Green
    fadeColors:
      - "0,0,255"         # Blue fade
```

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `star` | Boolean | `false` | Firework star (display-only shape) |
| `flicker` | Boolean | `false` | Twinkle / flicker effect |
| `trail` | Boolean | `false` | Trail of particles |
| `type` | String | `BALL` | Shape: `BALL`, `BALL_LARGE`, `STAR`, `CREEPER`, `BURST` |
| `colors` | List | — | Launch colors in `R,G,B` or `A,R,G,B` format |
| `fadeColors` | List | — | Fade-to colors in `R,G,B` or `A,R,G,B` format |

### target

Set the target player for placeholders in the item name and lore.

```yaml
item:
  material: DIAMOND_SWORD
  target: "%zmenu_argument_player%"  # Use a placeholder that resolves to a player name
  name: "&6&l%player_name%'s Sword"
```

So if the target placeholder resolves to "Notch", the item name will display as "Notch's Sword" for that player.

### attribute-merge-strategy

Define how attribute modifiers should merge with existing item attributes. Default: `ADD`.

```yaml
item:
  material: DIAMOND_SWORD
  attributes:
    - attribute: ATTACK_DAMAGE
      amount: 10
      operation: ADD_NUMBER
      slot: MAINHAND
  attribute-merge-strategy: REPLACE
```

<details>
    <summary>Click to show merge strategy options</summary>

    **Merge Strategies:**
    - `REPLACE` - Replace all existing attributes with the defined ones.
    - `ADD` - Add the defined attributes to the existing ones.
    - `KEEP_HIGHEST` - For each attribute, keep the highest value between existing and defined.
    - `KEEP_LOWEST` - For each attribute, keep the lowest value between existing and defined.
    - `SUM` - Sum the values of existing and defined attributes together.

</details>

### skip-first-cache

Prevent the item from being pre-built and cached on inventory load. Useful when the item depends on a player context that is not available at load time.

```yaml
item:
  material: PLAYER_HEAD
  player-head: "%player%"
  skip-first-cache: true
```

This is mainly relevant when using materials or placeholders that require a live player to resolve correctly.

## Saving a held item (`/zm save`)

Instead of writing an item by hand, you can build it in-game and export it:

```
/zm save <name> [yml|base64]
```

- Permission: `zmenu.save`, player only, the item must be in your main hand.
- The result is written to `plugins/zMenu/save_items.yml` under `items.<name>`. The name must be unused, otherwise the command refuses to overwrite.
- `base64` (default) stores `material: "base64:<data>"`, an exact copy of the item.
- `yml` converts the item to the normal item format described on this page (`name`, `lore`, `enchantments`, `flags`, `attributes`, `components`, ...). Copy the block into a menu or into the `items/` folder.

With `yml`, zMenu rebuilds the converted item and compares it with the original. If anything differs, or a setting has no matching component, the whole item is saved as `base64:` instead and the chat message lists the components that could not be written as YAML.

Version behaviour of the conversion:

- Paper 1.21.3+: every data component overridden on the item is converted to its zMenu [component](./components) (including `custom-data` from the persistent data container).
- Older servers: the item's `ItemMeta` is read instead, and settings such as flags, `hide-tooltip` and `fire-resistant` are exported as item options.

Only non-default values are written: for example `amount` is omitted when it is 1, `lore-type` when it is `REPLACE`, and `model-id` when it is 0. Colors of potions, leather armor and firework effects are written as `alpha,red,green,blue`, and enchantments are written as `name,level`.

## Troubleshooting / FAQ

| Console message | Cause and fix |
|-----------------|---------------|
| `Amount type X is not valid at ...amount-type` | Unknown `amount-type`. Use one of the values listed in the message (see [amount-type](#amount-type)). The default is used instead. |
| `Lore type X is not valid at ...lore-type` | Unknown `lore-type`. Use one of the values listed in the message (see [lore-type](#lore-type)). |
| `Item rarity X is not valid at ...item-rarity` | Unknown rarity. Use one of the values listed in the message. |
| `an error occurred while loading the enchantment X` | The enchantment is written wrongly. Each entry must be `name,level` or `name:level` (for example `sharpness,5`) with a level that is a whole number and an enchantment name that exists on your server version. The faulty entry is skipped, the others still load. |
| `Trim pattern 'X' was not found ...` / `Trim material 'X' was not found ...` | The trim key does not exist. The message lists the available ones. |
| `Invalid namespace for trim pattern/material` | The trim key is not a valid namespaced key (for example `minecraft:coast`). |
| `Color X is not valid ..., expected numbers between 0 and 255` | A `color` value is malformed. Use three numbers from 0 to 255. |
| `Leather material X has no armor type ..., its color will be ignored` | `color` was set on an item that is not leather armor. Remove it or change the material. |
| `Equipment slot X is not valid` | The `armor` material loader received an unknown slot. Use one of the slots listed in the message. |
| `Error while applying ItemComponent 'X' for item ...` | The component was read correctly but could not be applied to the item when it was built (usually a value that does not exist on your server version). The item is still created without that component. |
| `Error with update display name for item ...` | The `name` could not be processed, often because of a broken placeholder or MiniMessage tag. |

:::warning Silent failures
Some mistakes produce **no message at all**:

- An error thrown while *loading* a component from `components:` is only printed when `enable-debug: true` is set in `config.yml`. Without it the component is silently skipped.
- A component key that does not exist (typo, or a component newer than your server) is silently ignored.
- Unknown entries in `flags` are silently skipped.
- The whole `components:` section is ignored on servers older than 1.20.5.

When a component does not appear on the item, enable `enable-debug`, run `/zmenu reload`, and check the console.
:::

:::tip Caching
`enable-cache-item-stack` (in `config.yml`, `true` by default) pre-builds each item once when the menu is loaded. Items that use PlaceholderAPI placeholders or a dynamic material are never pre-built, and `skip-first-cache: true` opts a single item out. If an item looks stale or the load logs errors about a missing player, set `skip-first-cache: true` on it.
:::

## Best Practices

1. **Use meaningful names** - Make item names clear and descriptive
2. **Format lore consistently** - Use separators and spacing for readability
3. **Hide unnecessary info** - Use flags to hide enchantments/attributes when not needed
4. **Use placeholders** - Make items dynamic with PlaceholderAPI
5. **Test with resource packs** - If using customModelData, verify the models display correctly
