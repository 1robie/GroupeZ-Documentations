# Dialogues

Dialogues are interactive popup windows that appear on screen, allowing players to interact with forms, confirmations, and action buttons. They provide a modern UI experience beyond traditional inventory menus.

:::warning Requirements
Dialogues require **Paper 1.21.7+**.
:::

## File Location

Dialogues are stored in the `plugins/zMenu/dialogs/` folder. Each YAML file represents one dialogue.

```
plugins/zMenu/dialogs/
├── welcome.yml
├── confirmation.yml
├── server-links.yml
└── feedback-form.yml
```

## Dialog Types

zMenu supports every vanilla dialog type:

| Type | Description |
|------|-------------|
| `notice` | Simple informational dialog with a body and optional inputs |
| `confirmation` | Yes/No confirmation dialog |
| `multi_action` | Multiple action buttons in a grid layout |
| `server_links` | Display server links as clickable buttons |
| `dialog_list` | A hub listing other dialogs, one button per dialog |

## Basic Structure

```yaml
name: "&6&lDialog Title"
external-title: "Window Title"
type: notice

can-close-with-escape: true
pause: false
after-action: CLOSE

body:
  # Body content sections...

inputs:
  # Input fields...
```

## Configuration Options

### name

The internal name of the dialog, displayed with color formatting.

```yaml
name: "&6&lWelcome Dialog"
```

### external-title

The window title shown in the dialog header. The legacy spelling `external_title` is accepted too. It is also the label of the button that opens this dialog from a [dialog list](#dialog-list). When it is empty, nothing is sent and the client uses the dialog name.

```yaml
external-title: "Server Information"
```

### type

The dialog type (default: `notice`). See [Dialog Types](#dialog-types) for details.

```yaml
type: notice
```

### can-close-with-escape

Allow players to close the dialog by pressing Escape (default: `true`).

```yaml
can-close-with-escape: true
```

### pause

Pause the game while the dialog is open (singleplayer-like behavior). Default: `false`.

```yaml
pause: false
```

### after-action

What happens after an action is performed (default: `CLOSE`). Only the key `after-action` is read.

| Value | Description |
|-------|-------------|
| `CLOSE` | Close the dialog |
| `NONE` | Do nothing, the dialog stays open |
| `WAIT_FOR_RESPONSE` | Show a waiting screen until the server sends another screen |

```yaml
after-action: CLOSE
```

### open-requirement

Requirements the player must meet to open the dialog. Same format as the `open-requirement` of an inventory.

### inventory-replacement

Redirects the dialog to a zMenu inventory instead. Same options as the [inventory replacement](./bedrock#inventory-replacement) of an inventory (`name`, `plugin`, `pages`, `mode`).

### fallback-inventory

Inventory opened instead of the dialog when the player's client cannot render dialogs (below Minecraft 1.21.6).

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `name` | String | none (required) | Inventory file name, without `.yml` |
| `plugin` | String | `zMenu` | Plugin that owns the inventory |
| `page` | Integer | `1` | Page to open |

```yaml
fallback-inventory:
  name: my_menu
  plugin: zMenu
  page: 1
```

### target-player-name-placeholder

Placeholder used for the target player name (default: `%player_name%`). The alias `target_player_name_placeholder` is also accepted.

## Body Content

The `body` section defines what content appears in the dialog. You can combine multiple content types.

### plain_message

Display text messages. Canonical type name: `dialog_plain_message` (alias `plain_message`).

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `messages` | List of strings | empty | Lines of text |
| `width` | Integer | `128` | Width of the message block |
| `localized-messages` | Section | none | Messages per client locale, e.g. `en_us: [...]` |

```yaml
body:
  welcome:
    type: plain_message
    messages:
      - "&6&lWelcome to our server!"
      - ""
      - "&7Server IP: &fplay.example.com"
      - "&7Discord: &fdiscord.gg/example"
    width: 400
```

### item

Display an item with optional tooltip. Canonical type name: `dialog_item` (alias `item`).

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `item` | Section | none | The item to display (same format as zMenu items) |
| `width` | Integer | `128` | Width of the item |
| `height` | Integer | `128` | Height of the item |
| `show-decoration` | Boolean | `true` | Show the item count and damage bar |
| `show-tooltip` | Boolean | `true` | Show the item tooltip on hover |
| `description.messages` | List of strings | empty | Text displayed next to the item |
| `description.width` | Integer | `512` | Width of the description |

```yaml
body:
  featured-item:
    type: item
    item:
      material: DIAMOND_SWORD
      name: "&b&lLegendary Sword"
      lore:
        - "&7A powerful weapon"
    show-decoration: true
    show-tooltip: true
    width: 200
    height: 150
```

## Input Fields

Dialogues can include interactive input fields in the `inputs` section.

### dialog_text

A text input field.

```yaml
inputs:
  feedback:
    type: dialog_text
    label: "&6Share your thoughts:"
    width: 400
    max-length: 200
    multiline:
      max-lines: 4
```

**Options:**

| Option | Type | Description |
|--------|------|-------------|
| `label` | String | Label displayed above the input (default: empty) |
| `label-visible` | Boolean | Show the label (default: `true`) |
| `width` | Integer | Width of the input field (default: `200`) |
| `default-value` | String | Pre-filled text (default: empty) |
| `max-length` | Integer | Maximum character count (default: `32`) |
| `multiline.max-lines` | Integer | Number of lines for multiline input (default: `0`, single line) |
| `multiline.height` | Integer | Height of the multiline field (default: `20`) |

The submitted value is available as the placeholder `%<input-key>%`.

### dialog_boolean

A Yes/No toggle.

```yaml
inputs:
  subscribe:
    type: dialog_boolean
    label: "&eWould you like updates?"
    text-true: "&a&lYES"
    text-false: "&c&lNo"
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `label` | String | empty | Label of the toggle |
| `initial-value` | Boolean | `true` | Initial state |
| `text-true` | String | `True` | Text shown when enabled |
| `text-false` | String | `False` | Text shown when disabled |

The value is available as `%<input-key>%` (`true`/`false`) and the displayed text as `%<input-key>_text%`.

### dialog_single_option

A single selection from multiple options.

```yaml
inputs:
  gamemode:
    type: dialog_single_option
    label: "&6Select your gamemode:"
    options:
      survival:
        id: "survival"
        display: "&2Survival"
      creative:
        id: "creative"
        display: "&bCreative"
      adventure:
        id: "adventure"
        display: "&6Adventure"
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `label` | String | empty | Label of the input |
| `label-visible` | Boolean | `true` | Show the label |
| `width` | Integer | `200` | Width of the input |
| `options.<key>.id` | String | option key | Value submitted as `%<input-key>%` |
| `options.<key>.display` | String | empty | Text displayed for the option |
| `options.<key>.initial` | Boolean | `false` | Selected by default (only the first `true` is kept) |

### dialog_number_range

A numeric slider.

```yaml
inputs:
  amount:
    type: dialog_number_range
    label: "&eSelect amount:"
    start: 1
    end: 64
    step: 1
```

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `label` | String | empty | Label of the slider |
| `width` | Integer | `200` | Width of the slider |
| `start` | Number | `0` | Minimum value |
| `end` | Number | `100` | Maximum value |
| `step` | Number | `1` | Step increment |
| `initial-value` | Number | midpoint of `start` and `end` | Initial value |
| `label-format` | String | `options.generic_value` | Translation key used to format the label |

## Dynamic Buttons

Dynamic buttons generate several body sections or inputs from a single template, repeated over a numeric range. They are useful when the number of elements depends on data (a placeholder) or when you would otherwise copy/paste the same block many times.

Both dynamic types share these options:

| Option  | Type    | Description                                   |
|---------|---------|-----------------------------------------------|
| `start` | Integer | First index, inclusive. Placeholder-aware.    |
| `end`   | Integer | Last index, inclusive. Placeholder-aware.     |

Inside the repeated template, the `%index%` placeholder is replaced with the current iteration number.

### dialog-dynamic-body-button

Placed in the `body:` section. Repeats a `body:` element (e.g. `dialog_plain_message`, `dialog_item`).

```yaml
body:
  dynamic_message:
    type: dialog-dynamic-body-button
    start: 1
    end: 5
    body:
      type: dialog_plain_message
      messages:
        - "&eThis is body section #%index%"
      width: 300
```

### dialog-dynamic-input-button

Placed in the `inputs:` section. Repeats an `input:` element (e.g. `dialog_text`, `dialog_boolean`). Each generated input is keyed `<button-name>_<index>`, so its submitted value is available as the placeholder `%<button-name>_<index>%`.

```yaml
inputs:
  # If the player types "Hello" in the first field, %my_input_1% will be "Hello"
  my_input:
    type: dialog-dynamic-input-button
    start: 1
    end: 3
    input:
      type: dialog_text
      label: "&6Enter value #%index%:"
      width: 300
      max-length: 50
```

See the bundled `dialogs/dynamic-dialog-example.yml` for a complete example.

## Notice Dialog

A simple informational dialog with optional inputs. The optional `notice` section is its single [action button](#action-button-options) (`label`/`text`, `tooltip`, `width`, `actions`).

```yaml
name: "&6&lServer Rules"
external-title: "Rules"
type: notice

can-close-with-escape: true
after-action: CLOSE

body:
  rules:
    type: plain_message
    messages:
      - "&c&lServer Rules"
      - ""
      - "&71. Be respectful to all players"
      - "&72. No cheating or exploits"
      - "&73. Follow staff instructions"
      - "&74. Have fun!"
    width: 350

inputs:
  accept:
    type: dialog_boolean
    label: "&eI agree to the rules"
    text-true: "&a&lAccept"
    text-false: "&c&lDecline"
```

## Confirmation Dialog

A dialog with Yes and No buttons.

```yaml
name: "&c&lConfirm Purchase"
external-title: "Confirmation"
type: confirmation

can-close-with-escape: true
after-action: CLOSE

body:
  message:
    type: plain_message
    messages:
      - "&7Are you sure you want to purchase"
      - "&6Diamond Sword &7for &a$500&7?"
    width: 300

confirmation:
  yes-text: "&a&lConfirm Purchase"
  yes-tooltip: "Click to confirm"
  yes-width: 200
  no-text: "&c&lCancel"
  no-tooltip: "Click to cancel"
  no-width: 200

yes-actions:
  1:
    success:
      - type: console-command
        commands:
          - "give %player% diamond_sword 1"
      - type: withdraw
        amount: 500
      - type: message
        messages:
          - "&aPurchase successful!"

no-actions:
  1:
    success:
      - type: message
        messages:
          - "&7Purchase cancelled."
```

### Confirmation Options

| Option | Description |
|--------|-------------|
| `yes-text` | Text on the Yes button |
| `yes-tooltip` | Tooltip when hovering Yes |
| `yes-width` | Width of Yes button |
| `no-text` | Text on the No button |
| `no-tooltip` | Tooltip when hovering No |
| `no-width` | Width of No button |

The Yes and No buttons are read from `confirmation.yes` and `confirmation.no`, and accept every [action button option](#action-button-options). The `yes-actions` and `no-actions` root sections are the legacy location of their actions.

## Multi-Action Dialog

A dialog with multiple action buttons in a grid.

```yaml
name: "&6&lTeleport Menu"
external-title: "Teleport"
type: multi_action

can-close-with-escape: true
after-action: CLOSE
number-of-columns: 2

body:
  header:
    type: plain_message
    messages:
      - "&7Select a destination:"
    width: 300

multi-actions:
  spawn:
    text: "&a&lSpawn"
    tooltip: "&7Teleport to spawn"
    width: 150
    actions:
      1:
        success:
          - type: close
          - type: player-command
            commands:
              - "spawn"
          - type: message
            messages:
              - "&aTeleporting to spawn..."

  shop:
    text: "&e&lShop"
    tooltip: "&7Visit the shop"
    width: 150
    actions:
      1:
        success:
          - type: close
          - type: player-command
            commands:
              - "warp shop"

  pvp:
    text: "&c&lPvP Arena"
    tooltip: "&7Enter the PvP arena"
    width: 150
    actions:
      1:
        success:
          - type: close
          - type: player-command
            commands:
              - "warp pvp"

  home:
    text: "&b&lHome"
    tooltip: "&7Teleport home"
    width: 150
    actions:
      1:
        success:
          - type: close
          - type: player-command
            commands:
              - "home"
```

### Multi-Action Options

| Option | Description |
|--------|-------------|
| `number-of-columns` | Number of buttons per row (default: `3`) |
| `multi-actions` | Map of action buttons (required, at least one) |
| `exit-button` | Optional button at the bottom of the dialog, also triggered by the Escape key. Accepts every [action button option](#action-button-options) |
| `text` | Button text |
| `tooltip` | Button tooltip |
| `width` | Button width |
| `actions` | Actions executed on click |

## Server Links Dialog

Display server links as clickable buttons. The optional `server-links` section is an [action button](#action-button-options) (exit button) and also takes `number-of-columns` (default: `1`).

```yaml
name: "&6&lServer Links"
external-title: "Links"
type: server_links

can-close-with-escape: true
after-action: CLOSE

server-links:
  text: "&6&lUseful Links"
  tooltip: "&7Click to open"
  width: 300
  number-of-columns: 2
  actions:
    1:
      success:
        - type: message
          messages:
            - "&aLink opened!"
```

## Dialog List

A `dialog_list` dialog is a hub: it shows one button per dialog listed under `dialogs:`, each labelled with the `external-title` of its dialog (or its name when it has none). Clicking a button opens that dialog. An example is generated in `dialogs/dialog_list-dialog.yml`.

```yaml
name: "&6&lServer Hub"
external-title: "&6Server hub"
type: dialog_list

can-close-with-escape: true
pause: false
after-action: CLOSE

number-of-columns: 2
button-width: 150

dialogs:
  - "default-dialog"                     # zMenu dialog, by file name or name
  - "multi_action-dialog"
  - dialog: "confirmation-dialog"        # same, written as a map
  - registry-key: "minecraft:server_links" # vanilla or datapack dialog

back-button:
  enabled: true
  label: "&7« Back"
  tooltip: "&7Return to the server hub"
  width: 150

exit-button:
  label: "&cClose"
  tooltip: "&7Close the server hub"
  width: 150
  actions:
    1:
      success:
        - type: message
          messages:
            - "&7See you soon!"

body:
  welcome:
    type: dialog_plain_message
    messages:
      - "&7Welcome &f%player_name%&7, pick a section below."
    width: 300
```

### Dialog List Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `dialogs` | List | - | The dialogs to list. Each entry is a zMenu dialog name (`name` or `plugin:name`, also written `dialog: <name>`), or a vanilla/datapack dialog written `registry-key: <namespace:key>` |
| `number-of-columns` | Integer | `2` | Number of buttons in a row |
| `button-width` | Integer | `150` | Width of each button (1-1024) |
| `back-button.enabled` | Boolean | `true` | Adds a back button to the listed dialogs |
| `back-button.label` | String | `Back` | Label of the back button |
| `back-button.tooltip` | String | empty | Tooltip of the back button |
| `back-button.width` | Integer | `150` | Width of the back button (1-1024) |
| `exit-button` | Section | none | Optional button at the bottom of the list, also triggered by the Escape key. Supports `label`, `tooltip`, `width` and `actions` |

**Good to know:**
- **Back button**: the client does not return to the list when a listed dialog is closed. The back button is added to the listed dialogs that have no exit button of their own (`multi_action`, `server_links` and `dialog_list`) so players can come back. `notice` and `confirmation` dialogs have no exit slot and are left unchanged. To write your own back button instead, give the dialog an `exit-button` with the [`dialog`](./buttons/actions#dialog) action.
- **Requirements**: listed dialogs whose `open-requirement` the player does not meet are hidden. The requirement is checked when the list is opened, because the client opens the listed dialogs on its own, without asking the server.
- **Nesting**: a list can contain other lists. How deep they can be nested is set by [`dialog-list-max-depth`](./config-yml#dialog-list-max-depth) in `config.yml` (default `4`).

## Action Button Options

Action buttons — the Yes/No buttons of a `confirmation`, a `notice` button, each entry of a `multi_action`, and the `server-links` button of `server_links` — share a common set of options.

### label, tooltip, width

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `label` | String | empty | Button text. `text` is accepted as an alias |
| `tooltip` | String | empty | Tooltip shown on hover |
| `width` | Integer | `100` | Button width |

### actions

The zMenu actions run by a `custom-click` button. They are read from `<button>.actions`, then from the legacy `<key>-actions` section (for example `yes-actions`), then from the root `actions` section.

### type

The kind of action performed when the button is clicked (default: `custom-click`).

| Value          | Description                                                                   |
|----------------|-------------------------------------------------------------------------------|
| `custom-click` | *(default)* Runs the zMenu `actions:` defined on the button.                  |
| `static`       | Runs a native client action (see `static-type` below), without a server round-trip. |

### static-type

Only used when `type: static`. The native client action to perform.

| `static-type`       | Required field | Description                          |
|---------------------|----------------|--------------------------------------|
| `OPEN_URL`          | `url`          | Open a URL in the player's browser   |
| `OPEN_FILE`         | `file`         | Open a local file                    |
| `RUN_COMMAND`       | `command`      | Run a command as the player          |
| `SUGGEST_COMMAND`   | `command`      | Pre-fill the chat box with a command |
| `COPY_TO_CLIPBOARD` | `text`         | Copy text to the clipboard           |

```yaml
multi-actions:
  website:
    text: "&bOur Website"
    type: static
    static-type: OPEN_URL
    url: "https://example.com"
```

### usage-limit

Maximum number of times the button can be activated (default: unlimited). Only used by `custom-click` buttons, as are `duration-limit` and `enable-placeholders`.

```yaml
usage-limit: 1
```

### duration-limit

A cooldown between activations. Either a plain number (seconds) or a section with a time unit:

```yaml
duration-limit: 5          # 5 seconds
```

```yaml
duration-limit:
  value: 2
  type: MINUTES            # SECONDS, MILLISECONDS, MINUTES, HOURS, ...
```

### enable-placeholders

By default, a `%` typed by the player in an input is escaped so submitted values cannot inject placeholders. Set this to `true` to keep placeholders in submitted values. Accepts a boolean (default: `false`), or a section to toggle it per input type: `text`, `boolean`, `single-option`, `number-range`.

:::info Backward compatibility
The nested form (`<key>.label`, `<key>.tooltip`, `<key>.width`, `<key>.actions`, `<key>.type`) is the new canonical layout, but the old flat keys (`yes-text`, `notice.text`, `multi-actions.<key>.text`, ...) still work, so existing dialog files do not need to be rewritten.
:::

## Opening Dialogs

### From Button Actions

Use the `dialog` action type in inventory buttons:

```yaml
items:
  open-dialog:
    slot: 13
    item:
      material: BOOK
      name: "&6Open Dialog"
    actions:
      - type: dialog
        dialog: "welcome"
```

### With Arguments

Pass arguments to the dialog:

```yaml
actions:
  - type: dialog
    dialog: "confirmation"
    arguments:
      - "diamond_sword"
      - "500"
```

### From External Plugin

Open a dialog from another plugin:

```yaml
actions:
  - type: dialog
    dialog: "my-dialog"
    plugin: "MyPlugin"
```

## Best Practices

1. **Keep dialogs focused** - One purpose per dialog
2. **Use clear labels** - Make inputs easy to understand
3. **Provide tooltips** - Help players understand button actions
4. **Test on target version** - Ensure Paper 1.21.4+ and PacketEvents are installed
5. **Handle all outcomes** - Define actions for all possible choices
6. **Use appropriate types** - Choose the right dialog type for your use case
